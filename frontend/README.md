# frontend — the marketplace website (section 3c)

Next.js App Router, wagmi and viem. A landing page that follows the design in [designs/](../designs/),
and the marketplace: post a job, fund it, and follow it through bidding, verified execution, payout
and refunds. How it all fits together:
[docs/team-c/09-how-the-marketplace-works.md](../docs/team-c/09-how-the-marketplace-works.md).

| Route | |
|---|---|
| `/` | Landing page (red / black / white, Inter Tight; halftone art generated by `scripts/make-halftones.py`) |
| `/marketplace` | Jobs, stats, post-and-fund form (model, input, bounty, deadline, on-chain zk proof), agents |
| `/tasks/[id]` | One job: progress, bids, receipt and zk proof, payout, refunds, settle |
| `/api/faucet` | Test PBT on the local chain only |

## Setup

```bash
cd frontend
npm install
```

Then `scripts/dev-up.sh` at the repo root starts the website at http://localhost:3000 along
with the chain and the services it needs. On its own: `npm run dev`.

## Wallets

- **Use local test account.** Hardhat account #3, which the local node signs for, so no key
  is in the browser. It holds 10,000 PBT after a deploy.
- **Connect MetaMask.** Add the network `http://127.0.0.1:8545`, chain id 31337. The site
  offers to switch to it. "Get test PBT" mints 1,000 PBT to the connected wallet (local chain
  only). After every restart of the local chain, clear MetaMask's memory of it (Settings →
  Advanced → Clear activity tab data): MetaMask numbers each transaction (the nonce) from its own
  history, and the fresh chain refuses numbers that don't follow on ("Nonce too high/low"). A
  wallet that's merely a block behind ("Nonce too low") is asked once more automatically. If a job
  got posted but its deposit failed, its page has a "Fund this job" button.

## Checks

```bash
npm run typecheck
npm run build
npm run e2e        # needs the stack running; drives Chrome through the landing page and five whole jobs
```

`e2e/full-job.mjs` checks the landing page and its Launch button, connects the test account, and
plays five jobs: a 300 PBT job with a zk proof checked on chain (four bids, lowest wins, 81% of the
bid paid, the rest refunded), a 50 PBT job without one (Nova stays out), a job on the model trained
with federated learning, a 60 PBT job created without its deposit and funded from its page, and a 5 PBT job nobody bids on that expires after the chain's clock is moved
past its deadline (whole bounty refunded). It also checks for page errors and sideways scrolling on a
phone. Set `CHROME_PATH` if Chrome isn't at `/usr/bin/google-chrome`, and `SCREENSHOT_DIR` to save screenshots.

## Other networks

`NEXT_PUBLIC_CHAIN=sepolia` (plus `NEXT_PUBLIC_RPC_URL`, `EXECUTION_URL`, `STORAGE_URL`) points the site
at Sepolia; the test account and faucet then disappear. See `.env.example` and
[docs/sepolia-checklist.md](../docs/sepolia-checklist.md).

## Layout

```
app/page.tsx                         landing page
app/(app)/marketplace/page.tsx       jobs, stats, post form, agents
app/(app)/tasks/[taskId]/page.tsx    one job: progress, bids, receipt, payout, refunds, settle
app/api/faucet/route.ts              test PBT on the local chain
components/landing/                  landing sections, figures, styles (CSS module)
components/                          wallet, post form, job list, agent board, pipeline
lib/                                 contract ABIs, wagmi config, chain choice, zk commitment, API hooks
public/landing/                      halftone artwork (scripts/make-halftones.py)
```

Job state comes from the execution service (`/exec/api/chain/*`). Job descriptions go to
storage (`/storage/*`). `next.config.mjs` proxies both, and `EXECUTION_URL` and
`STORAGE_URL` override the targets.
