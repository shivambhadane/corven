Infrastructure for trusted autonomous systems

Contain one compromised agent. Not the whole network.

AI agents hold wallets, APIs and each other's trust. When one is compromised, CORVEN maps what it can actually reach, plans the smallest safe containment, and keeps the proof of what happened.

See an example incident What is built today →

Engineering evidence · as of 6 Nov 2026

  • 367 automated tests
  • Real PostgreSQL, no database mocks
  • Audit history append-only in the database
  • Graph measured at 1,000 nodes · 5,000 edges

Switching off one agent rarely contains an incident. Its delegated authority, shared resources and downstream workflows keep working for the attacker, and revoking them blindly breaks agents that did nothing wrong.

CORVEN works out the smallest boundary that stops the first without causing the second.

Discover

Built · discovery in progress

A registry of agents and resources, and typed dependencies between them: authority, resource and operational. Each relationship keeps its provenance, confidence, freshness and full version history. Automatic discovery from configurations, workflows and runtime events is the next module.

Analyze

Graph built · blast radius planned

An immutable, directed graph rebuilt from the registries. Ask who can reach what, by which path, filtered by dependency type, status and confidence. Reachability is structural: it shows connection, not compromise.

Contain

Planned

The central capability: the smallest set of authorization changes that blocks the compromised paths while keeping healthy workflows reachable. Shared or uncertain changes wait for a human, and every action explains why it is proposed.

Walk through the example →

Verify

Planned

Containment is not reported as success because a transaction was submitted. CORVEN retries the blocked operation, tests a healthy workflow, and compares what it expected with what it observed. Partial or failed outcomes stay visible.

Prove

Planned

Each stage of the incident becomes a hash-linked record that others can check without trusting CORVEN. Today the registries already keep append-only versions and audit rows enforced by the database; hashing, signing and external anchoring are still to build.

Design goals

What the response should achieve.

  • A smaller blast

    Cut what the compromised agent controls, and leave shared resources working for everyone else.

  • Decisions you can read

    Deterministic rules over the graph, with the paths and reasons behind each proposed action. No language model approves or enforces.

  • Honest outcomes

    Planned, approved, submitted, executed and verified are different things, and a partial response is never reported as contained.

Limits

A response layer, not a guarantee.

  • It can only enforce on systems and operations routed through its own enforcement points.
  • It cannot reverse completed blockchain transactions or revoke independent credentials it does not control.
  • It cannot discover dependencies invisible to its configured sources. The absence of a relationship is not proof none exists.
  • Reachability in the graph is structural: it does not mean an agent is compromised or a path is exploitable.
  • Containment involving shared resources or uncertain dependencies may require human approval.
