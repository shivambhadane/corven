Infrastructure for trusted autonomous systems

Contain the compromised agent.
Keep the healthy ones running.

AI agents hold wallets, APIs, credentials and each other's trust. When one is compromised, switching it off is not enough, and revoking everything it touched breaks agents that did nothing wrong. CORVEN finds what the agent can actually reach, calculates the smallest safe boundary, verifies it held and records what happened.

The problem

One compromised agent is rarely one problem.

Most controls look at a single identity, permission or transaction. The risk sits in the connections between them.

  1. 01

    Delegated authority

    A compromised agent may pass authority to others or hold it on someone else's behalf. Its identity alone doesn't show that.

  2. 02

    Shared resources

    Revoking a shared API or credential for everyone stops the attacker and also stops every healthy agent using it.

  3. 03

    Hidden downstream effects

    Operational dependencies carry the incident to agents that never touched the compromised one directly.

  4. 04

    No proof it worked

    Teams often cannot show that the compromised path is blocked, that healthy workflows still run, or what was done and when.

Approach

Five capabilities, one deterministic chain.

Security decisions are made by explicit rules over a dependency graph, not by a language model. AI can help explain; it never approves or enforces.

  • Discover

    Map agents, permissions, resources and workflows, with the evidence and confidence behind every relationship.

  • Analyze

    Trace dependencies from the compromised agent and separate authority, resource and operational exposure.

  • Contain

    Compute the smallest set of authorization changes that blocks the attack paths while keeping healthy workflows reachable.

  • Verify

    Retry the blocked operation, test a healthy workflow, and compare expected with observed.

  • Prove

    Produce hash-linked evidence of the incident and response that others can check independently.

How it works

From signal to evidence.

  1. MapAgents, resources and typed dependencies (authority, resource, operational) form a directed graph.
  2. DetectA compromised agent or suspicious operation opens an incident.
  3. Calculate impactTrace affected agents, resources and workflows, with the paths that explain each.
  4. Plan containmentChoose the smallest safe set of changes. Shared or uncertain ones wait for a human.
  5. Enforce and verifyApply through controlled enforcement points, then test blocked and healthy paths.
  6. RecordStore a hash-linked incident timeline with signatures and transaction references.

Design principles

What it will and won't do.

  • Deterministic enforcement. Decisions never depend solely on an AI model.
  • Least disruption. Protect healthy workflows wherever possible.
  • Verifiable response. Actions produce evidence you can check independently.
  • Explicit authority. Only what CORVEN controls can be directly revoked.
  • Planned, approved, submitted, executed and verified containment are kept distinct. Submitting a transaction is not success.
  • A partial response is never reported as contained.
  • Missing evidence is not treated as proof a dependency is gone.
  • No claim to control agents or credentials outside its enforcement boundary.

Limits

CORVEN is a response layer, not a guarantee.

  • It can only enforce on systems and operations routed through its own enforcement points.
  • It cannot reverse completed blockchain transactions or revoke independent credentials it does not control.
  • It cannot discover dependencies invisible to its configured sources. The absence of a relationship is not proof none exists.
  • Reachability in the graph is structural: it does not mean an agent is compromised or that a path is exploitable.
  • Containment involving shared resources or uncertain dependencies may require human approval.
