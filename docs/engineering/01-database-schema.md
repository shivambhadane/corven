## Conventions

- `id uuid` primary keys, generated by the database.
- `organization_id uuid NOT NULL` on every table. There is no organizations table yet, so it has no foreign key.
- Timestamps are `timestamptz`; `created_at` defaults to now; `updated_at` is set by the application.
- Enumerations are `varchar` with CHECK constraints (easier to evolve than enum types).
- Child tables reference parents with composite foreign keys `(parent_id, organization_id)`, `ON DELETE RESTRICT`.

## Agent Registry

### `agents`
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| organization_id | uuid | |
| name | varchar(120) | not blank |
| description | text | nullable |
| agent_type | varchar(32) | `llm`, `workflow`, `service`, `wallet`, `other` |
| status | varchar(32) | `active` (default), `suspended`, `compromised`, `inactive` |
| runtime_type | varchar(64) | nullable |
| owner_reference | varchar(255) | nullable |
| external_reference | varchar(255) | nullable; the stable key for entity resolution |
| metadata | jsonb | default `{}` |
| created_at, updated_at | timestamptz | |

Constraints and indexes: `UNIQUE (id, organization_id)`; unique `(organization_id, lower(name))`; unique partial `(organization_id, lower(external_reference))` where not null; indexes on `(organization_id, status)`, `(organization_id, agent_type)`, `(organization_id, created_at, id)`; CHECKs for status, type and non-blank name.

### `agent_capabilities`
`id`, `agent_id` → agents, `capability` varchar(100), `created_at`. Unique `(agent_id, capability)`. Descriptive data only, not authorization.

### `agent_identities`
`id`, `organization_id`, `agent_id`, `identity_type` (`ens`, `evm_address`, `did`, `api_client`, `other`), `identity_value` varchar(255), `verification_status` (`unverified` default, `pending`, `verified`, `failed`), `chain_id`, `verified_at`, timestamps. Unique `(organization_id, identity_type, lower(identity_value), coalesce(chain_id, 0))`. CHECK: `verified_at` is set exactly when status is `verified`.

### `agent_status_history` (append-only)
`id`, `organization_id`, `agent_id`, `previous_status` (null only for the initial registration entry), `new_status`, `actor_id`, `reason`, `incident_id` (not validated yet), `created_at`.

### `agent_audit_logs` (append-only)
`id`, `organization_id`, `agent_id`, `actor_id`, `action` (`agent.created`, `agent.updated`, `agent.status_changed`, `agent.capabilities_changed`, `agent.identities_changed`, `agent.identity_verification_recorded`), `before_state` jsonb, `after_state` jsonb, `created_at`.

## Dependency Registry

### `resources`
`id`, `organization_id`, `name` varchar(120), `resource_type` (`api`, `database`, `wallet`, `credential`, `storage`, `service`, `workflow`, `mcp_server`, `queue`, `other`), `description`, `external_reference`, `metadata`, timestamps. Unique `(id, organization_id)`, unique `(organization_id, lower(name))`, unique partial `(organization_id, lower(external_reference))`. A `credential` resource is a reference, never the secret.

### `dependencies`
| Column | Notes |
|---|---|
| id, organization_id | |
| source_type, source_agent_id, source_resource_id, source_id | `agent` or `resource`; exactly one reference column set; `source_id` is a generated `coalesce(...)` |
| target_type, target_agent_id, target_resource_id, target_id | same for the target |
| dependency_type | `authority`, `resource`, `operational` |
| relationship | varchar(100) label |
| metadata, provenance | jsonb |
| confidence | double, CHECK 0 to 1 |
| observed_at, last_verified_at | nullable timestamptz |
| status | `active` (default), `inactive` |
| version | integer ≥ 1, starts at 1, +1 per recorded change |
| created_at, updated_at | |

Constraints:
- four composite FKs `(source_agent_id | source_resource_id | target_agent_id | target_resource_id, organization_id)` → `agents` or `resources` `(id, organization_id)`;
- CHECK: type/reference consistency on both sides, no self-reference, confidence range, non-blank relationship;
- CHECK `dependencies_type_matrix_check`: authority is agent→agent; resource is agent→resource; operational is anything except resource→resource;
- unique `(organization_id, source_type, source id, target_type, target id, dependency_type)`: one relationship per ordered pair and type, regardless of status.
Indexes on `(org, source…)`, `(org, target…)`, `(org, dependency_type, status)`, `(org, created_at, id)`.

### `dependency_versions` (append-only)
`id`, `organization_id`, `dependency_id`, `version`, `change_type` (`created`, `updated`, `activated`, `deactivated`, `removed`), `changed_by`, `state` jsonb (full snapshot), `created_at`. Unique `(dependency_id, version)`.

### `dependency_audit_logs` (append-only)
`id`, `organization_id`, `dependency_id`, `actor_id`, `action` (`dependency.created|updated|activated|deactivated|removed`), `before_state`, `after_state` (the removal reason is stored inside `after_state`), `created_at`.

### `dependency_evidence` (append-only)
`id`, `organization_id`, `dependency_id`, `source_type` (`manual`, `agent_configuration`, `workflow_definition`, `permission_configuration`, `runtime_event`, `external_integration`), `source_reference`, `discovery_run_id` (no FK until discovery tables exist), `evidence_kind` (`declared`, `configured`, `observed`), `evidence_reference`, `source_version`, `confidence` (CHECK 0 to 1), `observed_at`, `created_at`. Partial unique index on `(dependency_id, discovery_run_id, source_type, coalesce(source_reference, ''))` where the run id is set, so retries cannot duplicate.

## Graph snapshots

### `graph_snapshots` (append-only)
`id`, `organization_id`, `label`, `incident_id` (not yet a foreign key), `created_by`, `node_count`, `edge_count`, `content_hash` (CHECK length 64), `payload` jsonb (the graph export), `built_at`, `created_at`. Unique `(id, organization_id)`; indexes on `(org, created_at, id)` and `(org, incident_id)`. The hash is verified on every load. See [../modules/graph-snapshot.md](../modules/graph-snapshot.md).

## Dependency Discovery

See [../modules/dependency-discovery.md](../modules/dependency-discovery.md) for behaviour.

- `discovery_sources`: per organization; `type` (`agent_configuration`, `workflow_definition`, `runtime_gateway`), `name` (unique per organization), `configuration` jsonb, `enabled`, `freshness_window_hours`, `last_successful_run_at`.
- `discovery_runs`: `source_id`, `status` (`pending`, `running`, `completed`, `completed_with_errors`, `failed`, `cancelled`), `summary` jsonb, `error_summary`, timestamps. A **partial unique index allows one active run per source**.
- `discovery_observations`: one per collected record: normalized proposal, `resolved` (matched entities and confidence), `processing_status` (`normalized`, `unresolved`, `rejected`, `pending_review`, `applied`, `review_rejected`), `reconciliation_outcome`, `registry_outcome`, redacted and size-limited `raw_evidence`.
- `discovery_reconciliation_results` (append-only): outcome and reason per observation or per missing/stale dependency.
- `discovery_reviews` (append-only): reviewer, decision (`approve`, `reject`, `defer`), reason.
- `discovery_runtime_events`: ingested gateway events, unique `(source_id, event_id)`, redacted payload, `consumed_run_id` so each event is read once.

All carry `organization_id` with composite foreign keys.

## Append-only enforcement

`corven_reject_mutation()` raises `restrict_violation` (SQLSTATE 23001). Row triggers reject `UPDATE` and `DELETE`, and statement triggers reject `TRUNCATE`, on: `agent_status_history`, `agent_audit_logs`, `dependency_versions`, `dependency_audit_logs`, `dependency_evidence`, `graph_snapshots`, `discovery_reconciliation_results`, `discovery_reviews`. Because parents are never hard-deleted (foreign keys are `RESTRICT`), history cannot be orphaned or erased through the normal path. A database superuser can still bypass triggers; see the threat model.

## What is not stored

The dependency graph. It is derived on demand. See [modules/graph-engine/](../modules/graph-engine/README.md).
